# BitBrush CI Design

## Goal

Add a GitHub Actions workflow that validates every pull request and push by
building the Java 21 application and running its Gradle test suite.

## Scope

- Create one workflow at `.github/workflows/ci.yml`.
- Trigger it for `pull_request` and `push` events.
- Use the repository's Gradle Wrapper to run `./gradlew build --no-daemon`.
- Set up Temurin Java 21, matching the Gradle toolchain.
- Use Gradle's setup action so dependency and build-state caching are managed
  by the action.
- Limit the workflow token to read-only repository contents.
- Cancel an in-progress run when a newer run supersedes it for the same pull
  request or branch.

## Explicitly Out of Scope

- Playwright production smoke tests. They target the live portfolio and
  backend rather than a local CI environment.
- Publishing build artifacts or JaCoCo coverage reports.
- Deploying to Fly.io or using deployment secrets.

## Workflow Shape

The `CI` workflow has one `build` job on `ubuntu-latest`:

1. Check out the triggering revision.
2. Provision Temurin Java 21.
3. Set up Gradle with its cache enabled.
4. Run the Gradle `build` lifecycle task. This compiles the application,
   executes the existing tests, creates the JAR, and generates the existing
   JaCoCo report.

The job depends only on public build inputs and requires no secrets or
write-level permissions, so it can also execute safely for pull requests.

## Validation

Validate the resulting YAML with an Actions-aware linter if available, and
run `./gradlew build --no-daemon` locally to prove the same command used by CI
works in this checkout.
